================================================================================

[ ] День 1. Аудит текущего состояния
    Задача: Выяснить, где сейчас хранятся результаты прогонов тестов в вашей компании.
    Вопросы для аудита:
        - Где лежат артефакты CI/CD? (GitHub Actions / GitLab CI / Jenkins)
        - Как долго хранятся логи прогонов?
        - Какие проблемы с flaky-тестами сейчас самые болезненные?
        - Сколько времени команда тратит на анализ падений?
        - Какой бюджет на CI/CD в месяц?
    Результат: Задокументированные боли команды и точки интеграции.

[ ] День 2. Установка JSON Репортера
    Задача: Модифицировать playwright.config.ts проекта.
    Команда в терминале:
        npm i -D @clipboard-health/playwright-reporter-llm
    Добавить в playwright.config.ts:
        reporter: [
          ['html'],
          ['@clipboard-health/playwright-reporter-llm', { 
            outputFile: './test-results/data.json' 
          }]
        ],
    Результат: Локальный прогон тестов создает файл data.json.

[ ] День 3. Изучение структуры JSON
    Задача: Понять, какие поля доступны для аналитики.
    Ключевые поля в JSON:
        - suites[].specs[].tests[].results[] — массив попыток выполнения
        - ok: boolean — пройден ли тест
        - duration: number — время выполнения в мс
        - retry: number — номер попытки (0 = первая)
        - error.message: string — текст ошибки
        - error.stack: string — стектрейс
        - steps[] — шаги теста с таймингами
        - attachments[] — скриншоты, trace, видео
    Результат: Понимание схемы данных для парсинга.

[ ] День 4-5. Написание парсера на Node.js
    Задача: Скрипт, который читает JSON и считает сводную статистику.
    Файл: parser.ts
    Базовые метрики для расчета:
        - totalTests: общее количество тестов
        - passedTests: количество пройденных
        - failedTests: количество упавших
        - flakyTests: тесты с retry > 0
        - passRate: (passed / total) * 100%
        - errorClusters: Map<errorMessage, count>
    Результат: Скрипт выводит в консоль сводку.

------------------------- УРОВЕНЬ 1: БАЗОВЫЕ МЕТРИКИ -------------------------
(реализуются в MVP, Неделя 1-3)

M1.1  Pass Rate                % пройденных тестов от общего числа
M1.2  Total Tests              Общее количество тестов в прогоне
M1.3  Passed / Failed Count    Количество пройденных / упавших тестов
M1.4  Flaky Tests Count        Количество тестов с retry > 0
M1.5  Flaky Ratio              % flaky-тестов от общего числа
M1.6  Total Duration           Общее время выполнения прогона
M1.7  Median Test Duration     Медианное время выполнения теста
M1.8  Error Clusters           Группировка ошибок по message
M1.9  Top Failing Tests        Топ-10 самых падающих тестов
M1.10 Runs History             История последних 10-20 прогонов

------------------------- УРОВЕНЬ 2: ПРОДВИНУТЫЕ МЕТРИКИ ---------------------
(реализуются после MVP, Неделя 4-6)

=== Производительность ===
M2.1  P95 / P99 Duration       95-й и 99-й перцентили времени тестов
M2.2  Slowest Tests            Топ-10 самых медленных тестов
M2.3  Duration Trend           Тренд времени прогона за 30 дней
M2.4  Phase Breakdown          Распределение времени: setup / tests / teardown
M2.5  Suite Duration           Время выполнения по тестовым наборам
M2.6  Duration per Browser     Время тестов в разрезе браузеров (Chrome/Firefox/WebKit)

=== Flaky-аналитика ===
M2.7  Flaky Score (0-100)      Взвешенная оценка нестабильности теста
                               Учитывает: частоту падений, паттерн, MTBF
M2.8  MTBF                     Mean Time Between Flakes — среднее время между падениями
M2.9  First Flake to Fix       Время от первого падения до исправления (в днях)
M2.10 Flaky Trend              Тренд количества flaky-тестов за 7/30/90 дней
M2.11 Flaky Pattern            Паттерн падений: всегда / случайно / только на CI
M2.12 Network Flakiness        % падений, вызванных сетевыми ошибками (5xx, timeout)
M2.13 Flaky Contagion Index    Корреляция падений между зависимыми проектами (0-1)

=== Качество кода тестов ===
M2.14 Test Smell Score (0-100) Оценка "запахов" в коде теста (чем ниже, тем лучше)
M2.15 POM Compliance           % тестов, использующих Page Object Model
M2.16 Assertion Density        Среднее количество expect() на один тест
M2.17 Wait Strategy Score      % "умных" ожиданий vs waitForTimeout
M2.18 Test Step Granularity    Среднее количество test.step на тест
M2.19 Test Isolation Score     Оценка независимости тестов (0-100%)
M2.20 Selector Stability Index Стабильность селекторов (% успешных использований)

=== Бизнес-метрики ===
M2.21 Time to Detect           Время от падения до уведомления команды
M2.22 Time to Fix (Flaky)      Среднее время от обнаружения flaky до исправления
M2.23 Cost of Flakiness        Стоимость flaky-тестов в рублях/месяц
                               = (ретраи × время × стоимость CI) + (время разработчика)
M2.24 Developer Friction       Количество ручных перезапусков пайплайна в день
M2.25 Release Confidence Score Композитный индекс готовности к релизу (0-100%)
                               = f(Pass Rate, Flaky Ratio, Coverage, Test Health)
M2.26 Automation ROI           Возврат инвестиций в автоматизацию (%)
                               = (Экономия - Затраты) / Затраты × 100%

=== Командные метрики ===
M2.27 Team Health Score        Агрегация метрик по команде (0-100)
M2.28 Tests per Developer      Количество тестов на разработчика
M2.29 Flaky per Team           Количество flaky-тестов в разрезе команд
M2.30 Cross-Project Correlation Корреляция метрик между проектами

------------------------- УРОВЕНЬ 3: AI/ML МЕТРИКИ -------------------------
(Enterprise-уровень, реализуются через 2-3 месяца)

M3.1  Predicted Flaky (Next)   Количество тестов, которые вероятно упадут в следующем прогоне
M3.2  Flaky Probability (0-1)  Вероятность падения для каждого теста
M3.3  Prediction Accuracy      Точность предсказаний модели (%)
M3.4  Root Cause Confidence    Вероятность, что причина падения — конкретный PR/коммит
M3.5  Suspicious PRs           Список PR, с высокой вероятностью вызвавших падения
M3.6  Auto-heal Suggestions    Количество предложенных AI-фиксов для тестов
M3.7  Auto-heal Success Rate   % успешно примененных AI-фиксов
M3.8  Anomaly Detection        Обнаружение аномалий во времени выполнения
M3.9  Test Impact Analysis     Предсказание, какие тесты затронет изменение в коде
M3.10 AI Confidence Score      Общая уверенность AI-модели в рекомендациях

================================================================================
                ПРИЛОЖЕНИЕ B: ФОРМУЛЫ РАСЧЕТА МЕТРИК
================================================================================

--- Базовые ---
Pass Rate (%)          = (PassedTests / TotalTests) × 100
Flaky Ratio (%)        = (FlakyTests / TotalTests) × 100
Flaky Tests Count      = COUNT(test WHERE retry > 0)

--- Flaky-аналитика ---
Flaky Score (0-100)    = (FailRate × 0.4 + PatternFactor × 0.3 + MTBF_Factor × 0.3) × 100
  где:
    FailRate           = FailedAttempts / TotalAttempts
    PatternFactor      = 1.0 для "всегда", 0.7 для "CI-only", 0.4 для "случайно"
    MTBF_Factor        = 1.0 если MTBF < 1 дня, 0.5 если 1-3 дня, 0.2 если > 3 дней

MTBF (дни)             = TotalDays / NumberOfFlakes

Network Flakiness (%)  = (FailuresDueToNetwork / TotalFailures) × 100

--- Качество кода ---
Test Smell Score       = SUM(Weight_i × SmellCount_i) / MaxPossibleScore × 100
  Веса запахов:
    - waitForTimeout          : вес 10
    - прямые локаторы         : вес 5
    - отсутствие POM          : вес 8
    - отсутствие test.step    : вес 3
    - жесткие ожидания        : вес 7

Wait Strategy Score    = (SmartWaits / TotalWaits) × 100
  где SmartWaits = waitForSelector + waitForResponse + waitForNavigation

Selector Stability (%) = (SuccessfulUses / TotalUses) × 100

--- Бизнес-метрики ---
Cost of Flakiness      = (CI_Cost + Developer_Cost) × WorkingDays
  где:
    CI_Cost            = RetriesPerDay × AvgRetryDuration × CI_MinuteCost
    Developer_Cost     = HoursSpentOnAnalysis × DeveloperHourlyRate

Release Confidence     = PassRate×0.4 + (1-FlakyRatio)×0.3 + Coverage×0.2 + TestHealth×0.1

Automation ROI (%)     = (SavedManualCost - AutomationCost) / AutomationCost × 100
  где:
    SavedManualCost    = ManualHoursSaved × QA_HourlyRate
    AutomationCost     = CI_Cost + MaintenanceCost + DeveloperTimeCost

Developer Friction     = ManualRerunsPerDay

--- Командные метрики ---
Team Health Score      = AVG(PassRate, 1-FlakyRatio, TimeToFix_Normalized, CodeQualityScore) × 100
